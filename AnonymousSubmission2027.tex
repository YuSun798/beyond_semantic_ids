\author{Anonymous Submission}

\begin{abstract}
Generative recommendation (GR) retrieves items by autoregressively decoding discrete Semantic IDs (SIDs) over learned codebooks, typically with finite-width beam search. We study how this practical search budget distributes retrieval support across items. We distinguish three quantities that are often conflated: whether an item has a unique code, whether it can be scored by an interface, and whether it actually appears in a finite top-$K$ output. To isolate the output interface, we introduce two continuous-query methods in a shared frozen item space: CQG-Single generates one query in a single forward pass, while CQG-AR autoregressively generates continuous residuals that refine the query. Both remove the item-token vocabulary and retrieve by dense scoring or approximate nearest-neighbor search. Controlled diagnostics show popularity-dependent SID target support and a depth-dependent transition in which SID decoding can be competitive at shallow $K$, while continuous retrieval can become more favorable deeper in the ranked list. CQG-AR provides an architecture-matched test of whether autoregression requires discrete SID outputs. Our results motivate matched-budget evaluation of discrete and continuous retrieval interfaces rather than treating catalog-wide scoreability as empirical top-$K$ coverage.
\end{abstract}

\section{Introduction}

Generative recommendation retrieves items by generating symbolic identifiers rather than directly scoring the entire catalog. The most influential instance of this paradigm is Semantic-ID (SID) recommendation: items are first quantized into discrete code sequences, and an autoregressive model decodes those sequences conditioned on user demographic and engagement feature \citep{rajput2023tiger,zheng2024letter,wang2024eager}. This formulation converts recommendation into a sequence-generation problem, and supports constrained decoding through a trie, ensuring that the generated token sequence corresponds to a valid item.

This marks a substantial architectural shift from conventional sequential recommenders. Models such as SASRec encode user histories, user features, and item representations, then score candidate items discriminatively \citep{kang2018sasrec}. In SID-based generative recommendation, the output interface is instead moved into a language-model-style generator: a decoder is trained to emit the SID sequence. Larger pretrained language models can provide useful generic knowledge and may benefit from scaling behavior as model and data size increase \citep{kaplan2020scaling}, but SID-based GR still requires three additional system components: First, items must be compressed into a finite hierarchical identifier space, using vector-quantization methods such as VQ-VAE \citep{vandenoord2017vqvae}, residual quantization as in RQ-VAE \citep{lee2022rqvae}, residual or balanced hierarchical clustering, or industrial generative retrieval designs such as OneRec \citep{deng2025onerec}. Second, the generator must be trained either by adapting a pretrained LLM through continued pretraining and supervised fine-tuning, where SID tokens become a new vocabulary that must be aligned with the LLM's semantic space, or by training a smaller decoder-only model from scratch, which sacrifices pretrained knowledge for a cleaner SID prediction objective. Third, inference decodes SID sequences from user features and sequential history, then maps the generated codes to item IDs or expands them through item-to-item retrieval. (Figure~\ref{fig:pipeline})

These steps introduce two practical bottlenecks: The first is coverage and updateability: a catalog item is useful only if its SID can be generated and mapped back to the item, but newly created items may cause semantical drift between the clustering model labeling and the item meaning. The second is support imbalance: a finite hierarchical SID space is a compromise for representing an open-ended catalog. Items are not distributed uniformly across SID leaves, semantic partitions can overlap, and the generated SID set may fail to recall enough valid items even when the related item catalog itself is large.

Moreover, the same discrete infrastructure also creates a structural bottleneck. SID systems depend on beam search at inference time. Beam search explores only a prefix-limited subset of the exponentially large code tree, and recent theoretical work shows that autoregressive tree generation imposes nontrivial expressiveness constraints \citep{hou2026expressiveness}. In other words, an item can have a valid SID and still receive zero retrieval probability if its path never enters the beam. This distinction is important: code assignment and code retrieval are different problems.

This paper asks a concrete question: \emph{how does finite beam search distribute support across the popularity spectrum?} Aggregate Recall@$K$ can hide this structure because it mixes popular and rare targets. We therefore stratify target support by training frequency and separately measure the union of actually retrieved top-$K$ items. We use TIGER \citep{rajput2023tiger} as the SID reference point. In the canonical ML-1M diagnostic, 99.4\% of items receive unique codes, yet only 63.8\% of held-out targets occur anywhere in the width-100 beam. The first statistic concerns code assignment; the second is a target-conditioned support rate, not catalog coverage. Their coexistence motivates studying inference-side exploration after code assignment succeeds. We additionally use matched resampling to control unequal target exposure across popularity strata.

This support limitation motivates a second empirical pattern that we call the \emph{Crossover Phenomenon}. At shallow retrieval depth, SID models can perform well because autoregressive decoding concentrates probability mass on high-confidence paths. On rare ML-1M targets, TIGER outperforms a continuous alternative at R@10; at deeper $K$, the continuous model catches up or overtakes. We treat this as a depth-dependent empirical transition, not as proof that a per-user hit rate equals an item-level catalog-coverage ceiling.

To isolate this mechanism, we study two complementary methods. \textbf{CQG-Single} is a deliberately minimal vocabulary-free model that maps user context to one continuous query in a frozen item space. \textbf{CQG-AR} retains a TIGER-like autoregressive decoder but replaces SID-token prediction with continuous residual generation, feeding each generated residual back to refine the query. Both retrieve by dense scoring or approximate nearest-neighbor (ANN) search without a code-to-item lookup. CQG-Single tests the simplest continuous interface, while CQG-AR controls for autoregressive model structure.

Our contributions are:
\begin{itemize}
    \item \textbf{Matched beam-support diagnostics.} We distinguish unique-code assignment, target-conditioned beam support, catalog-wide scoreability, and empirical union-of-top-$K$ coverage, and stratify the output-based quantities by item popularity.
    \item \textbf{Crossover Phenomenon.} We identify a depth-dependent tradeoff: SID decoding can win at shallow top-K precision, but continuous retrieval overtakes at deeper K as the beam-search ceiling binds.
    \item \textbf{Parallel continuous-query methods.} We introduce CQG-Single, a one-step continuous retriever, and CQG-AR, an autoregressive continuous decoder. Their comparison separates the effect of autoregression from the effect of a discrete SID vocabulary.
    \item \textbf{Controlled empirical study.} Across ML-1M, Amazon Beauty, and Amazon Sports, we analyze retrieval quality, reranked performance, loss functions, LLM backbone failures, and tokenization instability while limiting scalability claims to the tested catalog sizes.
\end{itemize}

\section{Related Work}



\textbf{Semantic-ID generative recommendation.}
TIGER \citep{rajput2023tiger} introduced hierarchical Semantic IDs using residual vector quantization and autoregressive decoding. Subsequent work improves code learning, alignment, and model design: LETTER integrates collaborative semantics \citep{zheng2024letter}, EAGER introduces behavior-semantic collaboration \citep{wang2024eager}, IDGenRec studies textual IDs \citep{tan2024idgenrec}, DIGER proposes differentiable indexing \citep{fu2026diger}, and UniGRec explores soft identifiers \citep{li2026unigrec}. These methods differ in how identifiers are constructed and aligned, but they retain a discrete vocabulary interface and typically require constrained autoregressive decoding. Our work targets a practical property of this family: finite-width search can allocate output support unevenly over a structured identifier space.

\textbf{Reachability and expressiveness limits.}
Theoretical work has begun to formalize limitations of tree-structured generative retrieval. \citet{hou2026expressiveness} show that autoregressive tree generation imposes correlation constraints that limit representable item distributions. This analysis motivates our empirical question: how do support constraints appear in practical SID-style recommendation pipelines? We complement this line of work by measuring target-conditioned beam support, matched-budget output coverage, and retrieval-depth behavior under controlled comparisons.

\textbf{Popularity bias in SID systems.}
Recent work also studies training-side popularity bias. For example, tail tokens may receive fewer updates under maximum-likelihood training, motivating modified objectives or tokenization schemes. Our analysis is complementary: even when code assignment succeeds, a held-out target can be absent from a finite beam. In our ML-1M experiments, 99.4\% of items receive unique codes, yet only 63.8\% of test instances have their target in the width-100 beam. Under matched-target resampling, popular-quartile targets still show substantially higher support than rare-quartile targets. This separates code-assignment success from inference-side exploration without conflating a per-user hit rate with catalog coverage.

\textbf{Vocabulary-free and continuous recommendation.}
Continuous alternatives avoid discrete item vocabularies. DiffuRec \citep{li2023diffurec}, DreamRec \citep{yang2023dreamrec}, and ContRec \citep{qu2026contrec} use diffusion or continuous latent generation. GPT4Rec \citep{li2023gpt4rec} generates textual queries for retrieval. CQG-Single occupies a deliberately minimal point in this design space, while CQG-AR preserves step-wise generation with continuous outputs. The contribution is not that continuous retrieval exists, but that these paired interfaces expose the SID reachability ceiling and separate discrete output constraints from autoregressive modeling.

\textbf{Sequential and dual-encoder recommendation.}
Sequential recommendation models such as GRU4Rec \citep{hidasi2016gru4rec}, SASRec \citep{kang2018sasrec}, and BERT4Rec \citep{sun2019bert4rec} score candidate items from user histories; P5 casts multiple recommendation tasks as language processing \citep{geng2022p5}. Dual-encoder retrieval originates from neural information retrieval \citep{huang2013dssm} and is widely deployed in large-scale recommendation \citep{covington2016youtube}. CQG-Single inherits the dense retrieval interface, whereas CQG-AR adds continuous autoregressive refinement. Their experimental role is to probe the vocabulary and beam-search assumptions in generative recommendation.

\textbf{Generative and hybrid retrieval.}
Generative retrieval in information retrieval directly decodes document identifiers, as in DSI and NCI \citep{tay2022dsi,wang2022nci}, and therefore shares questions about identifier design and constrained decoding with SID recommendation. LIGER explicitly combines dense and generative retrieval for sequential recommendation and studies their effectiveness and efficiency tradeoffs \citep{yang2024liger}. Our study is complementary: we compare finite-output support under matched budgets and use CQG-AR to separate autoregressive decoding from a discrete identifier vocabulary. These prior systems also make clear that dense retrieval is not itself our novelty claim.

\textbf{Scope of novelty.}
Dense retrieval and its catalog-wide scoring property are established techniques; we do not claim either as a new retrieval architecture. Our contribution is a controlled comparison in a shared frozen item space, together with item-level and popularity-stratified measurements of finite SID output support and its depth-dependent interaction with Recall@$K$. CQG-Single supplies a minimal dense control, whereas CQG-AR tests the same question with autoregressive continuous outputs. This design separates code assignment from code retrieval without attributing gains to a larger item encoder or a more elaborate ranker.
\section{Method}

\subsection{Problem Formulation}

Let $\mathcal{I}$ be a catalog of $N$ items and let user $u$ have a chronological interaction sequence $s_u=(i_1,\ldots,i_t)$. The task is to retrieve the next item $i_{t+1}$. SID-based GR maps each item $i$ to a discrete code sequence $z_i=(z_{i,1},\ldots,z_{i,L})$ and trains an autoregressive model $p(z_i\mid s_u)$. Inference uses beam search over valid code prefixes.

Both of our continuous methods assume a frozen item embedding matrix $E\in\mathbb{R}^{N\times d}$, where each row $e_i$ is an L2-normalized item vector. They condition on the same user context $c_u$ available to the SID decoder, including the sequential item history and, when available, demographic features. They differ in whether the continuous output is produced in one step or autoregressively.

\subsection{CQG-Single: Single-Step Continuous Query Generation}

CQG-Single learns a single-step query generator $f_\theta$:
\begin{equation}
q_u = f_\theta(c_u), \quad q_u\in\mathbb{R}^d .
\end{equation}
The recommendation score is cosine similarity:
\begin{equation}
\operatorname{score}(u,i)=q_u^\top e_i .
\end{equation}
The top-K items are retrieved by exact dense scoring or ANN search. Every item in $E$ is scoreable by construction, although catalog-wide scoreability does not guarantee that every item will empirically appear in a finite top-$K$ list.

The query generator is a compact causal Transformer. Each history item embedding $e_{i_j}\in\mathbb{R}^{64}$ is projected to hidden dimension $D=256$ and combined with a learned position embedding:
\begin{equation}
x_j = W_{\mathrm{in}} e_{i_j}+p_j .
\end{equation}
Four pre-norm causal self-attention blocks with four heads and feed-forward dimension 1024 process the sequence. The final hidden state is projected back into the item space:
\begin{equation}
q_u = W_{\mathrm{out}} h_t .
\end{equation}
The model has 3.2M trainable parameters, approximately 45\% fewer than the TIGER configuration used in our ML-1M comparison.

\subsection{CQG-AR: Autoregressive Continuous Query Generation}

CQG-AR retains an autoregressive decoder but replaces discrete SID-vocabulary prediction with continuous residual generation. At decoding step $\ell$, the decoder conditions on the user context and all previous continuous outputs:
\begin{align}
h_\ell &= D_\phi(c_u,\Delta_{<\ell}),\\
\Delta_\ell &= W_{\mathrm{AR}}h_\ell,\\
\hat e_u^{(\ell)} &=
\operatorname{norm}\!\left(\hat e_u^{(\ell-1)}+\Delta_\ell\right).
\end{align}
The generated residual $\Delta_\ell$ is projected back into the decoder input space and appended as the next autoregressive input. After $L$ steps, the refined query $\hat e_u^{(L)}$ retrieves items from the same frozen embedding matrix $E$. Thus CQG-AR preserves the conditional, step-wise decoding structure of SID retrieval while removing the SID vocabulary, codebook lookup, and discrete beam expansion. We use $L=3$ as an architecture-matched control for the three-level SID output, rather than assuming that three continuous refinements are intrinsically necessary. The $L=1$ setting is its single-step boundary and provides a controlled link to CQG-Single.

\subsection{Training Objectives}

We evaluate three objectives to expose the accuracy--scalability tradeoff. For CQG-Single, $q_b$ below is the single generated query. For CQG-AR, it is the final refined query $\hat e_b^{(L)}$; we additionally apply discounted catalog-level supervision to intermediate refinements.

\textbf{Full-catalog cross-entropy.}
Our primary objective treats retrieval as classification over all items:
\begin{equation}
\mathcal{L}_{\mathrm{CE}}
= -\frac{1}{B}\sum_{b=1}^{B}
\log
\frac{\exp(q_b^\top e_b^+/\tau)}
{\sum_{j=1}^{N}\exp(q_b^\top e_j/\tau)} ,
\end{equation}
where $\tau=0.07$. CE gives complete catalog visibility at training time but costs $O(N)$ per step.

\textbf{Bayesian personalized ranking.}
For larger catalogs, we use one positive and one sampled negative:
\begin{equation}
\mathcal{L}_{\mathrm{BPR}}
=-\frac{1}{B}\sum_{b=1}^{B}
\log \sigma(q_b^\top e_b^+ - q_b^\top e_b^-).
\end{equation}
BPR scales independently of $N$ but provides weaker training-time catalog coverage.

\textbf{Mean-squared error.}
We also test direct embedding regression:
\begin{equation}
\mathcal{L}_{\mathrm{MSE}}
=\frac{1}{B}\sum_{b=1}^{B}\|q_b-e_b^+\|_2^2 .
\end{equation}
MSE preserves geometric alignment but yields lower retrieval precision than CE in our experiments.

\subsection{Retrieval and Reranking}

Standalone CQG-Single ranks items according to $q_u^\top e_i$, while CQG-AR uses $(\hat e_u^{(L)})^\top e_i$. For larger catalogs, exact scoring can be replaced with an ANN index such as FAISS \citep{johnson2021faiss}. CQG-AR can also expose multiple intermediate or interest-specific queries, execute ANN for each, and merge their candidates under a fixed total candidate budget. We evaluate a modular retrieve-and-rank pipeline in which the continuous generator retrieves 100 candidates and a pretrained SASRec model reranks only those candidates.

\subsection{Contrast with SID Retrieval}

Figure~\ref{fig:pipeline} compares the inference mechanisms. SID retrieval requires codebook learning, autoregressive discrete decoding, beam search, and code-to-item lookup. Under a finite beam budget, only a restricted subset of valid code paths is explored. CQG-Single uses single-step continuous generation, whereas CQG-AR retains autoregressive decoding with continuous outputs. Both continuous variants query a dense index without introducing an item-token vocabulary.
\section{Experiments}

\subsection{Experimental Setup}

\textbf{Datasets.}
We use MovieLens-1M (ML-1M), Amazon Beauty, and Amazon Sports. ML-1M is the primary controlled diagnostic because its catalog is small enough for exact full-catalog scoring. Beauty and Sports test cross-domain behavior. Our processed Sports split (21,519 users and 10,694 items) differs from the commonly reported 5-core split used by TIGER, LETTER, and EAGER; consequently, we do not directly compare our Sports values with their published numbers. We exclude Yelp because its SID and continuous baselines are not aligned under one evaluation protocol.

\textbf{Protocol.}
We use leave-one-out evaluation: the last item is held out for testing, the second-to-last item for validation, and earlier interactions for training. Historical items are excluded from ranking. We report Recall@K and NDCG@K, primarily for $K\in\{10,30,50,70,90\}$ in reachability analysis and $K\in\{5,10,20\}$ in cross-dataset evaluation.

\textbf{Baselines.}
We compare against SASRec \citep{kang2018sasrec}, TIGER-style SID retrieval \citep{rajput2023tiger}, and reported SID results from TIGER, LETTER, and EAGER where protocols permit contextual comparison. We also include non-learned dense retrieval baselines: random retrieval, last-item kNN, and mean-of-5 kNN.

\textbf{Model training protocol.}
We first train SASRec on the same chronological next-item task used by the baselines, freeze its item embeddings, and then train the query generator in that fixed space. The multimodal Sports experiment instead freezes a fusion of these embeddings and ImageNet-pretrained ResNet-18 features. Holding the item space fixed isolates the retrieval interface; full architecture and objective details appear in Section~\ref{app:training}.

\section{Results}

\subsection{Finite-Beam Target Support}

For a fixed SID model and beam width $B$, target support is the fraction of test users whose held-out target occurs anywhere in the unfiltered beam. On ML-1M, the canonical seed-42 TIGER-style model has TargetSupport@100 of 63.8\%. This is a per-user quantity closely related to Recall@100; it is not the fraction of catalog items retrieved. Table~\ref{tab:reachability} stratifies this target-conditioned diagnostic by target popularity. We report empirical catalog coverage separately as the union of top-$K$ output items under a matched $K$ for SID, CQG-Single, and CQG-AR.

This target-conditioned metric is affected by the unequal number and frequency of targets in each popularity group. Figure~\ref{fig:reachability} visualizes the raw skew. We therefore also repeatedly sample the same number of distinct test-target items from each quartile and measure whether each sampled target occurs in the beam for its associated test instance. Table~\ref{tab:exposure-normalized} reports this matched-target diagnostic for the TIGER-style SID model. Tables~\ref{tab:reachability} and~\ref{tab:exposure-normalized} are SID-only beam diagnostics; they do not combine CQG-Single and CQG-AR. \paragraph{How many continuous decoding steps are necessary?}
Table~\ref{tab:ar-depth} varies CQG-AR depth while holding the seed, architecture, data, objective, and intermediate-loss weight fixed. Increasing $L$ from one to four does not monotonically improve shallow accuracy: all four R@10 values lie within 0.0035, and $L=1$ is competitive with the three-step SID-matched variant. This indicates that, in the current frozen item space, a single 64-dimensional continuous query can retain most of the useful retrieval signal obtained by the multi-step control. The practical implication is fewer serial decoder calls: $L=1$ removes two refinement rounds relative to $L=3$, while both avoid discrete beam expansion. We interpret this as an architectural efficiency advantage, not as measured end-to-end latency or a claim that one vector universally replaces every hierarchical SID.

\section{Analysis}

\subsection{Loss Objective Tradeoff}

Table~\ref{tab:loss} compares objectives on frozen embeddings using the corrected leave-one-out evaluator, which appends the validation item to the test history. Full-catalog CE produces the strongest Recall@10, while MSE and in-batch InfoNCE provide weaker catalog discrimination; Figure~\ref{fig:ce_mse} summarizes the contrast. The temperature ablation in Appendix~\ref{app:temperature} preserves this ordering.

This objective effect is a competing explanation for any continuous--SID accuracy gap: full-catalog CE exposes each continuous query to every item at each update, whereas the SID decoder receives token-level supervision over code positions. CQG-AR matches the broad autoregressive architecture but does not by itself match catalog visibility. We therefore report a sampled-CE control with a fixed 256-negative budget and avoid attributing an accuracy difference solely to the output interface. The interface claim supported without this assumption is narrower: CQG-Single and CQG-AR eliminate discrete code lookup and make every encoded item scoreable, while their finite top-$K$ coverage and accuracy remain empirical quantities.

\subsection{LLM Backbone Investigation}

We also tested whether a pretrained LLM backbone improves continuous query generation. Multiple Qwen configurations across three paradigms produced a negative but informative result (Figure~\ref{fig:llm_diagnostic}). \subsection{Tokenization Instability}

The auxiliary experiments also expose fragility in our discrete tokenization implementation. Several neural RQ-VAE configurations collapsed to degenerate codebooks with less than 10\% utilization. A k-means fallback achieved high code utilization but showed large downstream variance depending on decoder configuration. We do not use these failures as evidence that all SID methods are weak; rather, they motivate careful baseline validation against published TIGER, LETTER, and EAGER results.

\subsection{Training and Retrieval Complexity}

The full-catalog CE used by CQG-Single and CQG-AR requires scoring every item during training, so the present experiments establish feasibility only at the catalog sizes reported in Table~\ref{tab:data}. CQG-AR additionally performs $L$ decoder refinements, trading inference cost for an architecture-matched continuous alternative to SID decoding. Sampled softmax, cached ANN hard negatives, and ANN retrieval are plausible extensions, but we do not evaluate million-item training, latency, or memory in this study. Likewise, inserting a new encoded item into a dense index is an interface property rather than evidence that either method will rank cold items well.

\section{Discussion}

\textbf{What the ceiling means.}
The reachability ceiling is not the same as poor model accuracy. For a fixed trained model and beam budget, a target outside the produced candidate set has zero chance of being recovered by a downstream reranker. This is a property of the realized model--search combination, not proof that the target is unrepresentable by every stronger SID implementation.

\textbf{Why the crossover matters.}
The Crossover Phenomenon describes a depth-dependent empirical pattern rather than a universal ranking theorem. At R@10, concentrated autoregressive probability can help; deeper in the list, finite beam support can become a bottleneck in the evaluated systems. CQG-Single and CQG-AR both keep every encoded item scoreable, but their query quality depends on embedding alignment. CQG-Single achieves the strongest current ML-1M R@10, whereas CQG-AR approximately matches TIGER-style accuracy with lower seed variance; this indicates that continuous output can preserve autoregressive modeling without requiring SID tokens, but autoregressive refinement is not automatically superior to one-step generation.

\textbf{Practical implications.}
For static catalogs with strong top-10 precision requirements, SID methods remain competitive. Continuous-query retrieval offers a simpler score-and-index interface and can coexist with existing rankers as a recall stage. The depth ablation further shows that a single continuous output is competitive with multi-step continuous refinement in our setting, so three-level generation is useful as an architecture-matched control but is not required for the strongest continuous-query design. This removes serial refinement steps in addition to avoiding SID beam expansion; whether the resulting interface yields better end-to-end latency, memory use, or cold-item accuracy at production scale remains to be measured.

\section{Limitations}

Our study has several limitations. Matched-target subsampling reduces unequal target counts across popularity groups but remains observational rather than a causal intervention on user demand. The strongest completed crossover analysis is on ML-1M; a protocol-matched Amazon crossover is required for full cross-dataset confirmation. Our TIGER-style comparison uses hierarchical k-means over SASRec embeddings, and our closer T5/RQ-VAE recipe still fails to reproduce the published Beauty R@10, as documented in Table~\ref{tab:published-sid} and Appendix~\ref{app:tiger_recipe}. Thus, its absolute effect sizes must not be generalized to a fully reproduced TIGER checkpoint. The current CQG-AR residual steps share one next-item target and provide only limited improvement over its $L=1$ boundary. Both continuous methods use full-catalog softmax in their strongest configurations, which needs sampling or ANN-negative approximations at million-item scale. Finally, CQG-Single and CQG-AR inherit preference-relevant errors in the frozen item space.

\section{Conclusion}

This paper studies finite-beam output support as a practical bottleneck in SID-based generative recommendation. In our evaluated models, target-conditioned support and empirical output coverage are incomplete and popularity-skewed, and a depth-dependent Crossover Phenomenon can emerge between SID decoding and vocabulary-free continuous retrieval. CQG-Single demonstrates a minimal one-step continuous query, while CQG-AR shows that an autoregressive decoder can replace discrete SID tokens with continuous residual outputs and retain competitive accuracy. The depth ablation finds no monotonic shallow-accuracy gain from additional continuous generation steps, indicating that one generated embedding can be a competitive and more serially efficient alternative to a three-level output in the evaluated setting. Together these results separate the value of autoregression from the constraints of a discrete output vocabulary and motivate protocol-matched evaluation of accuracy, target support, and matched-budget catalog coverage.

\subsection{Dataset Splits}
\label{app:splits}

All datasets are converted into chronological user sequences. For each user, we use the last interaction for testing, the penultimate interaction for validation, and all earlier interactions for training. Users with insufficient history after filtering are removed. Evaluation is full-catalog unless otherwise stated: the target item is ranked against all candidate items rather than against sampled negatives. The reported top-$K$ metrics use $K\in\{5,10,20,30,50,70,90\}$ when available.

\subsection{Evaluation Metrics}
\label{app:metrics}

For a user $u$ with held-out target item $i_u^\star$, Recall@$K$ is one if $i_u^\star$ appears in the top-$K$ list and zero otherwise. NDCG@$K$ discounts a hit by the target rank. We distinguish two output-based support metrics. The SID target-support rate is
\[
\mathrm{TargetSupport@B} =
\frac{1}{|\mathcal{U}|}
\sum_{u\in\mathcal{U}}
\mathbf{1}\{i_u^\star\in \mathrm{Beam}_B(u)\},
\]
where $\mathrm{Beam}_B(u)$ is the unfiltered set of items decoded with beam width $B$. This is a per-user target-conditioned quantity and is closely related to Recall@$B$; it must not be interpreted as catalog coverage. For any method $M$, empirical union coverage at a matched output budget $K$ is
\[
\mathrm{CatalogCoverage@K}(M)=
\frac{\left|\bigcup_{u\in\mathcal U}\mathrm{TopK}_M(u)\right|}
{|\mathcal I|}.
\]
We report this same output-set quantity for TIGER, CQG-Single, and CQG-AR. Catalog-wide scoreability of a dense interface is a separate property and does not imply 100\% CatalogCoverage@$K$.

For the matched-target diagnostic, we first group distinct test-target items by training-frequency quartile. Let $\mathcal{Q}^{\mathrm{test}}_q$ be the test targets in quartile $q$ and let $m=\min_q|\mathcal{Q}^{\mathrm{test}}_q|$. For each trial, we uniformly sample $S_q\subseteq\mathcal{Q}^{\mathrm{test}}_q$ with $|S_q|=m$ and compute:
\[
\mathrm{MatchedTargetSupport}_q =
\frac{1}{m}
\sum_{i\in S_q}
\mathbf{1}\{i\text{ is supported for its associated test instance}\}.
\]
We report the mean and standard deviation over 200 trials. This equalizes the number of distinct sampled targets, but it is not a substitute for the matched CatalogCoverage@$K$ measurement above.

\subsection{Continuous-Query Dataloader}
\label{app:cqg_dataloader}

CQG-Single and CQG-AR use the same next-item examples derived from user histories. Each training example contains a padded history sequence and the next-item target. The history item IDs are mapped to frozen item embeddings before entering the query generator; the target ID is used either to index the target embedding for MSE/InfoNCE or to index the full-catalog label for CE. A batch therefore has the form
\[
(\mathbf{H}, \mathbf{y}) =
\{([i_{t-L},\ldots,i_{t-1}], i_t)\}_{b=1}^{B},
\]
where $L$ is the maximum sequence length and $B$ is the batch size. Padding positions are masked and never treated as candidate items. This dataloader is intentionally the same sequential next-item protocol used by SASRec, so the comparison isolates the output interface rather than changing the recommendation task.

\subsection{Continuous Query Training Objectives}
\label{app:cqg_losses}

The MSE variant regresses the generated query $q_u$ to the frozen target embedding $e_{i^\star}$:
\[
\mathcal{L}_{\mathrm{MSE}} =
\|q_u - e_{i^\star}\|_2^2.
\]
The InfoNCE variant treats other targets in the batch as negatives:
\[
\mathcal{L}_{\mathrm{NCE}} =
-\log
\frac{\exp(q_u^\top e_{i^\star}/\tau)}
{\sum_{j\in\mathcal{B}}\exp(q_u^\top e_j/\tau)}.
\]
The CE variant scores the full frozen catalog:
\[
\mathcal{L}_{\mathrm{CE}} =
-\log
\frac{\exp(q_u^\top e_{i^\star}/\tau)}
{\sum_{j=1}^{N}\exp(q_u^\top e_j/\tau)}.
\]
All variants can score every encoded item by dense similarity at inference time. Their empirical CatalogCoverage@$K$ is nevertheless measured from the union of finite top-$K$ outputs.

\section{SID Construction and Decoder Training}
\label{app:sid}

\subsection{Semantic-ID Construction}
\label{app:sid_construction}

The SID baseline follows the TIGER-style pipeline. First, a SASRec encoder is trained on the same chronological sequences used by both continuous methods. Its learned item embedding matrix is frozen and clustered by hierarchical k-means. Each item receives a depth-3 code path. The resulting tuple of cluster indices is treated as the target token sequence for the autoregressive decoder. Code collisions are resolved by assigning residual tie-break identifiers when needed, but in the reported ML-1M run collisions are negligible: 99.4\% of items receive unique codes.

\subsection{TIGER T5/RQ-VAE Reproduction Recipe}
\label{app:tiger_recipe}

Our closer Beauty reproduction loads the available precomputed SID array
\texttt{Beauty\_t5\_rqvae.npy}; the three decoder seeds do not retrain the
RQ-VAE tokenizer. The file assigns a distinct complete code to each of 12,101
items in the corresponding Beauty data directory. We train the provided
T5-style encoder--decoder separately with seeds 42, 43, and 44. Each run uses
200 maximum epochs, batch size 256, learning rate $10^{-4}$, inference batch
size 96, beam width 30, and early stopping after ten validation checks without
improvement in NDCG@20. The model has approximately 4.59M trainable
parameters. Its input is the serialized user interaction history and its
target is the next item's multi-token SID; training minimizes teacher-forced
autoregressive token cross-entropy. At inference, beam search generates SID
sequences that are mapped back to catalog items.

The exact command template is:
\begin{quote}
\small\ttfamily
python main.py --dataset\_path ../data/Beauty\\
--code\_path ../data/Beauty/Beauty\_t5\_rqvae.npy\\
--num\_epochs 200 --batch\_size 256 --infer\_size 96\\
--lr 1e-4 --beam\_size 30 --seed \{42,43,44\}.
\end{quote}

\subsection{TIGER-Style Dataloader}
\label{app:tiger_dataloader}

The SID decoder dataloader uses the same history-target pairs as CQG-Single and CQG-AR, but replaces the target item ID with its code tuple. Each batch contains a padded item-history sequence and a target SID sequence. Training minimizes token-level cross-entropy over the code positions. At inference, beam search expands partial SID prefixes under the code trie, maps completed codes back to item IDs, and returns the ranked decoded items.

\section{Dynamic Catalog Discussion}
\label{app:dynamic}

CQG-Single and CQG-AR share the same index-level update interface. A new encoded item can be inserted into the ANN index without adding an output token, rebuilding a code trie, or changing either model's output dimensionality. This interface property does not guarantee cold-item ranking quality. In contrast, a SID system must assign the new item to a code path; if the assignment changes the code distribution or causes collisions, the codebook, trie, and decoder may need to be refreshed. A direct dynamic-catalog evaluation would hold out a fraction of items during training, insert them into the retrieval index only at test time, and measure new-item Recall@$K$, warm-item Recall@$K$, index update cost, and whether model retraining is required.
